# 面试证据工作台 · AI × HR

把候选人材料变成带原文依据的电话初筛提纲。招聘人员可以看到每项能力的原文引文、模型建议的追问，以及仍需核实的地方，再决定哪些内容写入提纲。

## 在一分钟内试用

下载或克隆源码，用浏览器打开 `index.html`，即可回放 3 个虚构案例。

| 案例 | 观察点 |
| --- | --- |
| 跨行业零售 | 从运动用品接待经历找到需求识别的可迁移证据，保留高客单顾问式销售的核实问题 |
| 招聘协调 | 从共享排期与候选人通知中找到证据，单独记录尚未体现的流程复盘经历 |
| 无来源引文 | 查看一条故意植入的销售引文如何被拦截，其对应追问无法进入导出的提纲 |

勾选「确认纳入提纲」并导出文本。修改材料后，需要重新校验输出。仓库仅使用虚构招聘样例，无需安装依赖、登录或提供密钥即可回放。

## 招聘场景

零售岗位电话初筛容易遇到这样的问题：候选人在其他行业做过相似的事，简历用词却与岗位描述不同。逐字匹配容易遗漏可迁移经历，模型自由归纳又可能放大材料没有支持的结论。本项目将初筛准备拆为岗位能力、证据原文和面试追问三部分。

设计灵感来自零售招聘中的跨行业经验复核，以及招聘协调中的候选人沟通。作品是独立原型，案例与输出均为模拟。

## 使用 AI 生成新提纲

1. 每行输入一项岗位能力，再粘贴虚构或已获授权的候选人材料。
2. 点击「复制 AI 提示词」，发给你选择的对话模型。将模型返回的 JSON 粘贴到「导入 AI 返回的 JSON」。
3. 点击「校验并展示」，检查证据与能力的关联、可迁移判断和追问的中立性，再逐项确认并导出。

浏览器版通过人工复制、导入连接模型。预置演示里的正常输出由 ChatGPT 在本项目协作中生成，异常案例包含一条人为植入的无依据引用。示例回放无需重新运行模型。

### 可选的本机调用

Python 3 无第三方依赖。设置 `OPENAI_API_KEY` 和 `OPENAI_MODEL` 为你可用的密钥和模型 ID，再运行：

```sh
python3 serve.py
```

打开 <http://127.0.0.1:8765>。「调用 OpenAI」在检测到配置后出现。经确认，当前提示词及材料将发送到 OpenAI [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)。密钥只在本机进程里使用。API 可能产生费用。本机服务只监听环回地址，公共静态页面使用样例回放或人工导入。

## 如何复核

| 检查 | 处理 |
| --- | --- |
| 缺少对应能力、重复能力、字段格式不合法 | 标为校验失败，阻止该行进入提纲 |
| 引文无法在候选人材料中逐字定位 | 标出引文，拦截对应追问 |
| 材料未体现某项能力 | 允许招聘人员审阅中性提问，证据字段为空 |
| 引文存在但可能断章取义 | 招聘人员回看材料，判断原文是否支持模型解读 |

原文校验能确认引文存在，语义是否准确仍需要人工判断。界面围绕面试准备设计，不生成录用、淘汰、打分或排名结果。项目尚未在真实业务中部署，未测量招聘效率提升。

## 测试与部署
